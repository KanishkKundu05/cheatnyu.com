6. With f (n) = 2n + 1 and g(n) = n2 , which of the given pairs c, n0 are appropriate
   for proving f (n) = O(g(n)) directly from the definition?

   Recall that we must exhibit positive constants c and n0 such that f (n) ≤ c g(n) for
   all n ≥ n0 . A candidate pair fails as soon as we can point to a single n ≥ n0 at
   which the inequality is violated.

   (a) c = 1 and n0 = 1.

       Solution. Testing at n = n0 = 1 gives f (1) = 2(1) + 1 = 3 and 1 · g(1) =
       1 · 12 = 1. The definition would require 3 ≤ 1, which is false.

       Answer: No — the inequality already fails at n = 1.

   (b) c = 2 and n0 = 1.

       Solution. Testing at n = n0 = 1 gives f (1) = 3 and 2 · g(1) = 2 · 12 = 2. The
       definition would require 3 ≤ 2, which is false.

       Answer: No — the inequality already fails at n = 1.

   (c) c = 2 and n0 = 5.

       Solution. Testing at n = n0 = 5 gives f (5) = 2(5) + 1 = 11 and 2 · g(5) =
       2 · 52 = 50, and indeed 11 ≤ 50. The inequality also continues to hold for every
       larger n, since for n ≥ 5
                2n2 − (2n + 1) = 2n(n − 1) − 1 ≥ 2 · 5 · 4 − 1 = 39 > 0.

       Answer: Yes — these are appropriate values.

                                           5
   (d) c = 200 and n0 = 1.

         Solution. Testing at n = n0 = 1 gives f (1) = 3 and 200·g(1) = 200·12 = 200,
         and indeed 3 ≤ 200. For every n ≥ 1 we also have

                              200n2 ≥ 200n = 2n + 198n ≥ 2n + 1.


         Answer: Yes — these are appropriate values.


   In summary, the appropriate choices are (c) and (d).

         Solution.    Write both products out explicitly. Each has exactly n terms:

                      n! = n · (n − 1) · (n − 2) · (n − 3) · · · 2 · 1   (n terms)

         the product into a sum:
                         (︁                               )︁

8. For each code snippet, determine whether the given property holds at the start of
   each loop iteration.

   Reminder on the convention. “The start of an iteration” means just after i is
   assigned its new value, before the body executes. This includes the final “dummy”
   iteration, in which i is assigned a value exceeding the loop’s upper bound and the
   body is therefore never run. A property is a loop invariant only if it holds at every
   one of these checkpoints, for every input array.

   (a)
             for i = 1 to n
                 A[i] = 3



                                                 7
      Property: all entries of A[1 : i − 1] are equal to 3.

      Solution. By the time the loop reaches index i, the body has already executed
      once for each of 1, 2, . . . , i − 1, and each such execution assigned the value 3 to
      that position. Every entry up to but not including the current i is therefore
      equal to 3. At i = 1 the range A[1 : 0] is empty, so the property holds vacuously.

      Answer: Yes. (Given as the example.)

(b)
          for i = 1 to n-1
              if A[i] < A[i+1]
                  exchange A[i] with A[i+1]

      Property: the elements in subarray A[1 : i − 1] are in increasing order.

      Solution. Take the counterexample A = [ 1, 3, 2 ], so n = 3 and the loop runs
      i = 1 to 2.

       • Start of i = 1: A = [ 1, 3, 2 ]. The range A[1 : 0] is empty, so the property
         holds vacuously. The body then finds A[1] = 1 < A[2] = 3 and swaps,
         giving A = [ 3, 1, 2 ].
       • Start of i = 2: A = [ 3, 1, 2 ]. The range A[1 : 1] = [ 3 ] consists of a single
         element and is therefore trivially in increasing order, so the property holds.
         The body then finds A[2] = 1 < A[3] = 2 and swaps, giving A = [ 3, 2, 1 ].
       • Start of i = 3 (the dummy iteration): A = [ 3, 2, 1 ]. Now A[1 : 2] =
         [ 3, 2 ], and since 3 > 2 this is not in increasing order. The property fails.

      Because the property is violated at the final checkpoint, it is not an invariant.

      Answer: No — counterexample A = [ 1, 3, 2 ], which the loop turns into
      [ 3, 2, 1 ].

      Remark. This loop makes a single left-to-right pass and swaps whenever A[i] <
      A[i + 1], so it pushes larger elements to the left. It therefore tends to leave
      the front of the array in decreasing order, which is the opposite of what the
      property claims.

(c)
          for i = 1 to n-1
              if A[i] < A[i+1]
                  exchange A[i] with A[i+1]

      Property: the element in position A[i − 1] (if it exists) is greater than or equal
      to all the elements in A[1 : i − 2].

9. Insertion-Sort, as given in the textbook:

       INSERTION-SORT(A, n)
       1   for i = 2 to n
       2       key = A[i]
       3       // Insert A[i] into the sorted subarray A[1 : i-1].
       4       j = i - 1
       5       while j > 0 and A[j] > key
       6           A[j+1] = A[j]
       7           j = j - 1
       8       A[j+1] = key


   (a) Run the algorithm by hand on A = [ 12, 8, 7, 3 ], showing the array at the start
       of each iteration of the outer loop, including the final iteration where i = n + 1.

       Solution. Below, the vertical bar separates the sorted prefix A[1 : i − 1] from
       the part of the array not yet processed.

        • Start of i = 2: A = [ 12 | 8, 7, 3 ]. Here key = A[2] = 8. Since 12 > 8, we
          shift 12 to the right and insert 8 in front of it.
        • Start of i = 3: A = [ 8, 12 | 7, 3 ]. Here key = A[3] = 7. Since 12 > 7 we
          shift 12 right, and since 8 > 7 we shift 8 right, then place 7 in front.
        • Start of i = 4: A = [ 7, 8, 12 | 3 ]. Here key = A[4] = 3. Since 12 > 3,
          8 > 3 and 7 > 3, all three elements shift right and 3 is placed in front.
        • Start of i = 5 (the final “dummy” iteration, i = n + 1): A = [ 3, 7, 8, 12 ],

                                            9
       which is fully sorted.

    The four required snapshots are therefore

                                 i=2:         [ 12, 8, 7, 3 ]
                                 i=3:         [ 8, 12, 7, 3 ]
                                 i=4:         [ 7, 8, 12, 3 ]
                                 i=5:         [ 3, 7, 8, 12 ]

(b) For the same input, how many times is the comparison A[j] > key in Line 5
    executed?

    Solution. We count the executions pass by pass. Note that when the while-
    loop ends because j has reached 0, the test j > 0 fails first, and by short-
    circuiting the comparison A[j] > key is not evaluated on that final pass through
    the test. In each pass below, therefore, the comparison is executed exactly once
    per shift.

                   Iteration    Comparisons      Detail
                     i=2             1           12 > 8
                     i=3             2           12 > 7, 8 > 7
                     i=4             3           12 > 3, 8 > 3, 7 > 3
                     Total           6


                                      1 + 2 + 3 = 6.

    Answer: 6 comparisons.
