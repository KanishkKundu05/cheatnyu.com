❖   Worst-case runtime of Heapsort is Ω(n log n) too!
❖      First n/2 calls to Max-Heapify are on heaps with ≥ n/2 elements
           and those heaps each have size ≥ log2(n/2) = log2 n − 1
                     (ignoring floors and ceilings)
❖      ⇒ First n/2 calls to Max-Heapify each take time ≥ c(log2 n − 1) in worst
    case   (worst-case: element at root has to bubble all the way down to a leaf)
❖      ⇒ Worst-case runtime of Heapsort is at least (n/2) ∗ c(log2 n − 1)
❖      ⇒ Worst-case runtime of Heapsort is Ω(n log n)
❖   So worst-case runtime of Heapsort is θ(n log n)

Priority Queue
          Priority Queue is an Abstract Data Type
❖   Stores set S of elements
❖   (Max) Priority queue implementation must support the following operations
    ❖   Insert(S,x,k)     Insert element x into S with key k
    ❖   Maximum(S)        Return element in S with largest key (but don’t remove)
    ❖   Extract-Max(S)    Remove and return element in S with largest key
    ❖   Increase-Key(S,x,k)    Increase key of element x of S to k (assume it is less
        than k)
❖   Could implement priority queue (PQ) using different data structures
❖   Example: Implementation of PQ using unsorted doubly-linked list
      ❖   Insert(S,x,k)       Insert element x into S with key k
             ❖   How? Insert element x with key k at front of doubly-linked list
             ❖   Worst-case Runtime of Insert(S,x,k)?    θ(1)
      ❖   Maximum(S)          Return element in S with largest key (but don’t remove)
             ❖   How?     Linear search (since doubly-linked list is unordered)
             ❖   Worst-case Runtime?     θ(n)    where n is number of elements in the priority queue
      ❖   Extract-Max(S)      Remove and return element in S with largest key
             ❖   How?        Look at all elements to determine max, then delete it from doubly linked list
             ❖   Worst-case Runtime?    θ(n) to determine max, θ(1) to delete
      ❖   Increase-Key(S,x,k)    Increase key of element x of S to k (assume it is less than k)
             ❖   How?        Linear search to find x, then increase key of x
             ❖   Worst-case Runtime?    θ(n) to find x, θ(1) to increase key of x

Some important concepts from probability
                      Linearity of Expectation


❖   We will use following important property called “Linearity of Expectation”
❖   For any two random variables X and Y, and constants a and b
      ❖   E[aX + bY] = aE[X] + bE[Y]
❖   True even if X and Y are not independent!

Quicksort
                                             Quicksort
❖   Very practical (with tuning)
❖   Divide-and-conquer
❖   Idea:
    ❖   Pick an element x of the array. Call it the “pivot”
    ❖   Partition the other elements with respect to the pivot, as follows:
             Elements ≤ x go on left side of array (low side), elements > x go on right side of array (high
        side)
             Pivot x goes in between the two sides
    ❖   Recursively sort the low side
    ❖   Recursively sort the high side
                              Partition example

❖   42893175
❖   Suppose pick 5 to be the pivot
❖   If use extra array, very easy to partition around pivot in time θ(n)
❖   We will do it in-place in time θ(n) (slightly more complicated)
                                                                     Partition example
❖   Idea to do in place:
       ❖   Pick last element of array to be the pivot
       ❖   Loop for j=1 to n-1, maintain invariant that the prefix A[1…j-1] of A is partitioned according to pivot
       ❖   Keep variable i that is highest index of element <= x in partitioned prefix A[1…j-1]. (initialize to 0)
       ❖   In body of loop, incorporate new element A[j] into the already partitioned prefix
       ❖    if A[j] > x, just leave where A[j] in place
             if A[j] <= x, increment i and exchange A[i] with A[j]
       ❖   At end: Move pivot to position i+1
