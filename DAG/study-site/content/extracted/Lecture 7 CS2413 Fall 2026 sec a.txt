                     IncreaseKey and “Handle”

❖   In order to do IncreaseKey(A,x,k), need to be able to locate element x in the
    array
❖   Implement a “handle” for x to map between elements and array positions
    ❖   Locate element x in the heap, i.e., map elements to array indices
    ❖   (Also, determine which element x is in a given array position, i.e.,map
        array positions to elements)
❖   Handle must be updated when elements move during operations on the heap
❖   One implementation of handle:
      ❖   add array position information to the element (object) itself
❖   This implementation has θ(1) overhead per position change of element in heap,
    but storing info in element violates “abstraction barrier”
❖   Another implementation of handle
    ❖   add array position information to the element (object) itself
        Use hashtable to map elements to array positions
❖   Need to update information when array position of x changes. Adds overhead.
❖   Above implementation has θ(1) overhead per position change, but storing info in element violates
    “abstraction barrier”
    Above implementation has O(1) overhead “on average” per position change but worst case is O(n).
    Respects abstraction barrier.
❖   Going forward, we’ll exclude the runtime of mapping operations from the
    runtimes.
