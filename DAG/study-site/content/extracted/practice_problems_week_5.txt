Problem 1 : Walking through Quicksort’s in-place partition
Recall the in-place partitioning process from lecture. Work through this process on A = [6, 3, 8, 2, 9, 5, 7, 4]
(pivot = A[8] = 4). For each value of j from 1 to 7, show whether A[j] ≤ x, what happens to i,
and the resulting array. Then show the final swap that places the pivot, and confirm the array is
correctly partitioned around 4.

  Solution. Pivot x = A[8] = 4. Start: i = 0, A = [6, 3, 8, 2, 9, 5, 7, 4].

                      j A[j] ≤ x?      Result
                      1  6    no       leave in place: [6, 3, 8, 2, 9, 5, 7, 4]
                      2  3   yes       i→1, swap A[1], A[2] : [3, 6, 8, 2, 9, 5, 7, 4]
                      3  8    no       leave in place: [3, 6, 8, 2, 9, 5, 7, 4]
                      4  2   yes       i→2, swap A[2], A[4] : [3, 2, 8, 6, 9, 5, 7, 4]
                      5  9    no       leave in place: [3, 2, 8, 6, 9, 5, 7, 4]
                      6  5    no       leave in place: [3, 2, 8, 6, 9, 5, 7, 4]
                      7  7    no       leave in place: [3, 2, 8, 6, 9, 5, 7, 4]
      Final step: swap A[i+1] = A[3] with the pivot A[8]: [3, 2, 4, 6, 9, 5, 7, 8].
      Final check: the low part of the array A[1:2] = [3, 2] are all ≤ 4, and the high part of the
  array A[4:8] = [6, 9, 5, 7, 8] are all > 4, with the pivot 4 correctly placed at index 3 in between
  the two parts of the array. The array is correctly partitioned.


Problem 2 : Indicator random variables and expectation

position i). Say position i is a fixed point if π(i) = i. Let X be the total number of fixed points
in π.

 (a) For i = 1, . . . , n, let Xi be the indicator random variable for the event that position i is a
     fixed point. What is P (Xi = 1)?

 (b) Express X in terms of X1 , . . . , Xn , and use linearity of expectation to find E[X].

 (c) The Xi ’s are not independent (e.g., knowing π(1) = 1 changes the probability that π(2) = 2,
     since now only n − 1 values remain for the other positions). Does that cause a problem for
     the computation in part (b)? Why or why not?

Problem 4 : Generalizing the box analogy
Recall in lecture, you discussed a nice example for where randomization helps.
    The example is as follows: with 2 boxes, one containing $100 and the other $0, a deterministic
“always pick Box 1” strategy can result in getting $0 in the worst case, while a randomized coin flip
strategy guarantees an expected $50 no matter where the money is hidden.
    Now generalize to k boxes: $100 is placed in exactly one of the k boxes (and $0 in the rest)
before you choose any boxes, and you don’t know which one holds the money.

 (a) If you use the deterministic strategy “always choose Box 1,” what is the worst case amount
     you receive, regardless of where the money is placed?
 (b) If you use the randomized strategy and choose uniformly at random among the k boxes, what
     is your expected gain? Explain why this value is the same regardless of which specific box the
     money has been placed in.
 (c) As k grows large, what happens to the deterministic strategy’s worst case result? What
     happens to the randomized strategy’s guaranteed expected gain?
 (d) Explain the connection to Randomized Quicksort. In what sense is choosing a pivot position
     analogous to choosing a box here, and what does this example suggest about why Randomized
     Quicksort avoids the guaranteed Θ(n2 ) worst case that the deterministic (always choose the
     last element as the pivot) version experiences on a sorted array?

 Solution. (a) If the money is placed in any box other than Box 1, then the worst case gain is
 $0.
      (b) Each box is chosen with probability 1/k, so regardless of which box actually holds the
 $100, the expected gain is k1 · 100 + k−1      100
                                        k · 0 = k . This doesn’t depend on which box the money
 is in, because the money is placed before you choose a box. From the perspective of the person
 hiding the money, every box is equally likely to be the one you pick, so every placement gives
 the same expected gain.
      (c) The deterministic strategy’s worst case stays exactly $0 forever regardless of the value of
 k. The randomized strategy’s expected gain, 100/k, moves toward 0 as k → ∞, but it is always
 strictly positive. However, this expected gain never collapses to the deterministic strategy’s $0
 worst case.
      (d) Choosing which element of the array to use as the pivot is analogous to choosing which
 box to open. A deterministic rule like always picking the last element in the array can be
 easily defeated by a specific input (e.g. a sorted array). Similarly, picking a deterministic rule
 like “always pick Box 1” can be easily defeated by placing the money in any box other than
 Box 1. Choosing the pivot uniformly at random instead is like randomizing which box you
 pick. No matter what the input array looks like, the expected outcome (here, expected running

 time) is controlled by an average over the randomized choice, rather than the worst possible
 randomized outcome. This means that there is no single fixed input that can force bad expected
 performance, exactly as no fixed box placement can force the randomized expected gain down
 to $0.


Problem 5 : How tight is the Ω(n log n) lower bound, concretely?
In lecture, you proved that any comparison sort algorithm requires Ω(n log n) comparisons in the
worst case, using the fact that its decision tree must have at least n! leaves, and a binary tree with
n! leaves has height at least log2 (n!). Let’s look more closely at this for a small value of n.

 (a) For n = 4, compute 4! and log2 (4!).

 (b) A decision tree of height h has at most 2h leaves. Using your answer to (a), find the smallest
     integer h such that 2h ≥ 4!. What does this tell you about the minimum possible worst case
     number of comparisons needed to sort 4 elements?

 (c) Insertion Sort’s worst case occurs on a reverse sorted input where the i-th element (for i =
     2, . . . , n) must be compared against all i−1 elements already placed before it stops (or reaches
     the front). Using this, compute the exact worst case number of comparisons Insertion Sort
     performs on 4 elements. Is it equal to your lower bound from (b)?

 (d) Given your answers to (b) and (c), do you think the Ω(n log n) bound is always possible with
     some comparison sort algorithm, for every n? What would it mean about an algorithm if its
     worst case matched the bound exactly?


 Solution. (a) 4! = 24, and log2 (24) ≈ 4.585.
      (b) We need the smallest integer h with 2h ≥ 24. Since 24 = 16 < 24 and 25 = 32 ≥ 24, we
 get h = 5. So any comparison sort algorithm must perform at least 5 comparisons in the worst
 case to sort 4 elements.
      (c) On a reverse sorted array of 4 elements, element 2 is compared against 1 earlier element,
 element 3 against 2 earlier elements, and element 4 against 3 earlier elements (each comparison
 fails until the new element reaches the front, so all are performed). This leaves us with 1+2+3 =
 6 comparisons, which is strictly greater than the lower bound of 5 from part (b). Thus, Insertion
 Sort is not optimal in the worst case for n = 4.
      (d) The bound from part (b) is a lower bound that holds for every comparison sort algorithm.
 Insertion Sort is one example of an algorithm that doesn’t meet it exactly. However, the bound
 can be tight. For n = 4, it turns out Merge Sort’s worst case is exactly 5 comparisons, which
 matches the lower bound precisely. An algorithm whose worst case matches log2 (n!) (rounded
 up) exactly, for a given n, is using every comparison as efficiently as an algorithm possibly can.
 No comparison sort algorithm could do better on n, in the worst case.
