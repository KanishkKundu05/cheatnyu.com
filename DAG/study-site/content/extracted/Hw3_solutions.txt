2. When we gave the running time of the priority queue operations in class, for the doubly-linked
list and heap implementations, we excluded the time for mapping operations. In this problem we
consider the heap implementation of the priority queue and the Increase Key operation, which
locates x in the heap and then bubbles it up using swaps.

(a) Under Handle A, what is the worst case cost of updating the handles for the two elements
    involved in a single swap during bubble-up? Summing over the whole bubble-up, what is the
    overall worst case runtime of Increase-Key?

    Solution. Under Handle A, updating the handles in a swap is O(1), and using the handle to
    locate x in the heap is O(1). The bubble-up performs O(log n) swaps, so

                                T (n) = O(1) + O(log n) · O(1) = O(log n).

    Answer: O(1) per swap; O(log n) overall in the worst case.

    Solution. There is one hash table lookup to locate x in the heap, plus two handle updates

                                        O(1) · O(log n) = O(log n).

                                       O(n) · O(log n) = O(n log n).

    Answer: Yes for Handle A; for Handle B, only in the average case.

(c) Suppose we try to solve this problem by dividing the array in half, recursively finding the pair
    with the largest overlap on each side, and returning whichever of the two pairs had the larger
    overlap. Why doesn’t this work, even if we add a suitable base case?

    because the only overlaps computed are the ones returned by the two recursive calls. A pair

(d) Design an algorithm that identifies all genuine watches using o(n2 ) comparisons.

    Solution.
    Throughout the pseudocodes, Same(x, y) returns true if watches x and y are made of the same
    materials. Additionally, the array of watches is denoted as W and the size of W is denoted as
    |W |.
    Approach 1: Divide-and-Conquer
    If a material is the majority of a segment, it must also be the majority of at least one of the
    segment’s two halves.
    Otherwise, if the material appeared in at most half of each half, it could not appear in more
    than half of the entire segment.
    Therefore, we can recursively find the majority candidate of each half and check whether either
    candidate is the majority of the entire segment.
     1: function solve(W )
     2:    if |W | = 1 then
     3:        return W [1]                                  ▷ A single watch is its own majority
     4:    end if
     5:    Split W into two approximately equal halves L, R        ▷ Divide into two subproblems
     6:    a ← solve(L)
     7:    b ← solve(R)                                    ▷ Find each half’s majority candidate
                                                     ▷ The overall majority must be among a, b
     8:    for each distinct non-None candidate c ∈ {a, b} do
     9:        count ← 0
    10:        for each watch x ∈ W do
    11:            if Same(c, x) then
    12:                count ← count + 1
    13:            end if
    14:        end for

    15:        if count > |W |/2 then
    16:            return c
    17:        end if
    18:    end for
    19:    return None                                       ▷ No majority exists in this segment
    20: end function

Approach 2: Boyer–Moore Majority Voting
Maintain one candidate watch and a counter. A matching material increases the counter,
while a different material decreases it. A decrease can be viewed as canceling a pair of watches
made from different materials. When the counter reaches zero, choose the next watch as a
new candidate. Because genuine watches form a strict majority, their material survives this
cancellation process. Finally, compare the surviving candidate with every watch to identify
the entire genuine group.

19:    return G
20: end function
